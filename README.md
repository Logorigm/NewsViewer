# NewsHub

Android-агрегатор новостей из RSS-лент, сайтов и публичных Telegram-каналов. Всё собирается в одну
ленту, одинаковые новости объединяются, есть прозрачный фильтр политики, избранное и чтение без
интернета.

- Язык: **Java 17**, Android SDK 35 (minSdk 26 — Android 8.0+)
- Сборка: **Gradle 8.9** (wrapper в репозитории), Android Gradle Plugin 8.7.3
- Архитектура: **MVVM** + репозитории + единый интерфейс `SourceProvider`
- Хранилище: **Room**. Фоновые задачи: **WorkManager**. Сеть: **Retrofit + OkHttp**

## Архитектура

```
 UI (Fragments, XML + Material 3)          ui/…
   │  observes LiveData
 ViewModels                                 ui/*/…ViewModel
   │
 Repositories                               data/repo
   ├─ NewsRepository     — обновление, лента, избранное, история, обслуживание БД
   ├─ SourceRepository   — каталог источников, проверка, редактирование
   └─ SettingsRepository — настройки в Room с кешем в памяти
   │                         │
 Room (data/db)          Источники (data/source) ── HTTP (data/net: Retrofit + OkHttp)
                           ├─ RssSourceProvider        (RSS 2.0 / RSS 1.0 / Atom + поиск ленты на сайте)
                           ├─ TelegramPreviewProvider  (публичное веб-превью t.me/s/…)
                           └─ DemoProvider             (только debug-сборка)
   │
 Domain (чистая Java, без Android; покрыт JVM-тестами)   domain/…
   parse/    RssParser, TelegramPreviewParser, FeedDiscovery, DateParser
   classify/ TopicClassifier, PoliticsRules, Term
   dedup/    ArticleFingerprint, SimilarityScorer, DedupIndex, StoryStats
   rank/     InterestRanker
   feed/     FeedFilter, PoliticsLimiter, Period, SortOrder, FeedMode
   text/     TextNormalizer, RussianStemmer, HtmlText, UrlNormalizer, TimeFormat

 WorkManager: work/RefreshWorker (периодическое обновление), NewsNotifier (уведомления)
```

**Как проходит обновление.** `NewsRepository.refreshBlocking()` выбирает источники, которым пора обновляться,
и опрашивает их параллельно (до 4 одновременно). Ответы обрабатываются последовательно в транзакции:

1. пропуск уже сохранённых записей (хеш guid, уникальный индекс `sourceId + guidHash`);
2. классификация по темам и политике;
3. поиск того же события среди публикаций за 72 часа;
4. запись и пересчёт статистики сюжета;
5. запись статуса источника: время, ошибка, ETag/Last-Modified, пауза перед следующей попыткой.

Ошибка одного источника не мешает остальным.

**Почему ручной контейнер вместо Hilt.** Граф зависимостей маленький (`AppContainer`). Так в Java-сборке
меньше аннотационных процессоров и проще читать, откуда берётся каждый объект.

## Источники

Источники хранятся в `app/src/main/assets/sources.json`. Список можно менять без правки кода: при запуске
приложение добавляет новые записи каталога и не трогает то, что пользователь уже изменил. Пользовательские
источники добавляются во вкладке «Источники». Дубликаты (тот же адрес или канал, в том числе в другой
категории) отклоняются и в каталоге (это проверяет тест), и в интерфейсе.

**Как проверялись адреса.** Каталог составлялся в окружении, где сайты изданий и `t.me` были недоступны
сетевой политикой. Поэтому адреса сверялись по открытым каталогам лент (Feeder, TGStat, Telemetr), страницам
самих изданий и публикациям в СМИ. Ни один адрес не придуман: если надёжного адреса нет, поле пустое, а
источник выключен. Настоящий статус каждого источника приложение показывает после первого обновления.

| Уровень | Значение |
|---|---|
| `CONFIRMED` | адрес подтверждён издателем или независимым каталогом лент |
| `KNOWN` | общеизвестный адрес, при сборке каталога не перепроверялся |
| `DISCOVERY` | указан только сайт; адрес RSS приложение находит на странице (`<link rel="alternate">`) |
| `UNVERIFIED` | адрес не найден; источник выключен, нужно указать адрес вручную |

### Telegram: что возможно, а что нет

- **Как это работает в приложении.** Используется публичная веб-страница канала `https://t.me/s/<канал>`.
  Это та же страница, которую Telegram показывает любому посетителю в браузере. Авторизация и ключи не
  нужны, от имени пользователя ничего не отправляется. Работает только для открытых каналов с включённым
  веб-превью. Видны последние ~20 постов. Это не документированный API: если Telegram изменит вёрстку,
  парсер придётся обновить. Источники Telegram можно отключить одним переключателем в настройках.
- **Bot API не подходит для чтения чужих каналов.** Бот получает посты канала только если он добавлен в этот
  канал администратором. Одного токена бота недостаточно, чтобы читать произвольные каналы.
- **Закрытые каналы и полная история** требуют клиентского API (MTProto/TDLib): `api_id`/`api_hash`,
  которые разработчик регистрирует на my.telegram.org, и вход пользователя по номеру телефона. Это не
  реализовано. Секретные ключи нельзя встраивать в APK.
- Доступ к `t.me` может ограничиваться провайдером. Тогда источник показывает сетевую ошибку, а остальные
  продолжают работать.

### Добавление нового типа источника

1. Реализуйте `data/source/SourceProvider` (метод `fetch` не должен бросать исключения: ошибки возвращаются
   через `ProviderResult`).
2. Добавьте значение в `domain/SourceType` и зарегистрируйте провайдер в `AppContainer`.

## Как работают фильтры и ранжирование

### Фильтр политики (`domain/classify/PoliticsRules`)

- Работает полностью на устройстве, без ИИ и платных API. Правила разбиты на три группы: внутренняя
  политика, международная политика, военные действия. Каждую группу можно отключить.
- У каждого слова есть вес: 3 — явная политика («госдума», «санкции»), 2, 1 — слабые слова
  («правительство», «губернатор», «президент»). Совпадение в заголовке считается дважды. Публикация
  политическая, если сумма не меньше порога: мягкая чувствительность — 7, обычная — 4, строгая — 2.
- Поэтому упоминание государства само по себе не делает новость политической: «Губернатор открыл школу»
  и «Правительство изменило правила ипотеки» порог не набирают (это проверяется тестами).
- Встроенные исключения («Звёздные войны», «президент клуба», «Война и мир»…), свои стоп-слова и свои
  исключения задаются в настройках. Весь список правил с весами открывается кнопкой «Как работает фильтр».
- Отдельный тумблер «Фильтр политики» и режим «ограничивать» или «скрывать». В режиме «ограничивать»
  остаются только сюжеты, о которых сообщили 2+ источника, и они занимают не больше 20% ленты. Режим ленты
  «Без политики» скрывает её всегда.
- Публикации **не удаляются**: фильтр работает на уровне запроса. Скрытое видно в разделе «Скрытые
  публикации» с причиной («сработали правила: …»). Любой сюжет можно отметить «не политика», и пометка
  применяется ко всем его публикациям. После изменения правил старые публикации пересчитываются.

### Группировка дубликатов (`domain/dedup`)

Для каждой публикации считается «отпечаток»:

- канонический URL без utm-меток, `www`, `m.`, `/amp`;
- основы слов заголовка (нормализация и лёгкий стеммер);
- пары слов из фрагмента текста;
- числа;
- имена собственные.

Две публикации объединяются в один сюжет, только если выполнены все условия:

- совпадает ссылка **или** заголовки достаточно похожи (Жаккар/вложенность по основам слов) и общих слов не
  меньше 2–3;
- разница во времени не больше 48 часов;
- числа в заголовках не противоречат друг другу («курс 95» ≠ «курс 97»);
- в заголовках нет разных главных имён («выставка Айвазовского» ≠ «выставка Шагала»);
- для двух публикаций одного источника нужен более высокий порог.

Если сходство есть, но уверенность низкая (`UNCERTAIN`), публикации **не объединяются**. В карточке
показываются число источников, время первой и последней публикации и ссылки на все оригиналы.

### «Только интересное» (`domain/rank/InterestRanker`)

```
score = 0.45 · свежесть (период полураспада 18 ч)
      + 0.20 · число независимых источников (log, насыщение на 5)
      + 0.35 · интерес к теме (базовый + «больше/меньше» + доля прочитанного по теме за 30 дней)
```

Прочитанное и политическое опускаются ниже. Затем идёт жадный отбор: штраф за повтор источника и темы
подряд, один источник даёт не больше 20% подборки. У каждой карточки есть «Почему?» со списком причин и
кнопками «больше/меньше такого». Число источников подаётся как «насколько широко освещается», а не как
подтверждение достоверности.

## Установка JDK, Android SDK и сборка APK

### 1. JDK 17

AGP 8.7 требует JDK 17 или новее (JDK 21 тоже подходит).

- Windows/macOS: установите [Temurin 17](https://adoptium.net/temurin/releases/?version=17).
- Linux (Debian/Ubuntu): `sudo apt install openjdk-17-jdk`.
- Проверка: `java -version`. Если в системе несколько JDK, укажите `JAVA_HOME` на JDK 17
  (или `org.gradle.java.home=/путь/к/jdk17` в `~/.gradle/gradle.properties`).

### 2. Android SDK

Вариант А — **Android Studio** (Ladybug или новее): откройте папку проекта, Studio сама предложит
установить нужные компоненты SDK.

Вариант Б — **только командная строка**:

```bash
# 1) Скачайте "Command line tools only" со страницы https://developer.android.com/studio#command-tools
mkdir -p ~/android-sdk/cmdline-tools
unzip commandlinetools-*_latest.zip -d ~/android-sdk/cmdline-tools
mv ~/android-sdk/cmdline-tools/cmdline-tools ~/android-sdk/cmdline-tools/latest

# 2) Переменные окружения (добавьте в ~/.bashrc или ~/.zshrc)
export ANDROID_HOME=$HOME/android-sdk
export PATH=$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH

# 3) Компоненты SDK и лицензии
sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0"
yes | sdkmanager --licenses
```

В Windows те же шаги: `ANDROID_HOME=%LOCALAPPDATA%\Android\Sdk`, команды `sdkmanager.bat`.

Укажите путь к SDK в файле `local.properties` в корне проекта (файл не коммитится):

```properties
sdk.dir=/home/<user>/android-sdk
# Windows: sdk.dir=C\:\\Users\\<user>\\AppData\\Local\\Android\\Sdk
```

Вместо `local.properties` можно задать переменную окружения `ANDROID_HOME`.

### 3. Gradle 8.9

Отдельно ставить Gradle не нужно: в репозитории есть wrapper, закреплённый на 8.9
(`gradle/wrapper/gradle-wrapper.properties`). При первом запуске `./gradlew` он сам скачает Gradle 8.9.

### 4. Сборка

```bash
# Linux/macOS
./gradlew assembleDebug
# Windows
gradlew.bat assembleDebug
```

Готовый APK: `app/build/outputs/apk/debug/app-debug.apk`. Установка на устройство:
`adb install -r app/build/outputs/apk/debug/app-debug.apk`.

**Release-сборка.** Создайте ключ
(`keytool -genkeypair -v -keystore newshub.jks -alias newshub -keyalg RSA -keysize 2048 -validity 10000`)
и файл `keystore.properties` в корне проекта (не коммитится):

```properties
storeFile=newshub.jks
storePassword=…
keyAlias=newshub
keyPassword=…
```

Затем выполните `./gradlew assembleRelease`, результат — `app/build/outputs/apk/release/app-release.apk`.
Без `keystore.properties` получится неподписанный `app-release-unsigned.apk`. Сжатие R8 выключено ради
стабильности. Чтобы включить, поставьте `minifyEnabled true` в `app/build.gradle`: правила уже лежат в
`proguard-rules.pro`.

**CI.** `.github/workflows/android.yml` на каждый push запускает тесты, собирает debug-APK и lint, а APK
прикладывает к запуску как артефакт.

## Известные ограничения

- **Проверка сборки.** Полная сборка подтверждена в GitHub Actions (Gradle 8.9, JDK 17): прошли все
  102 unit-теста (88 JVM + 14 Robolectric/Room), собран `app-debug.apk`, lint завершился без ошибок. На
  устройстве и в эмуляторе приложение вручную не прогонялось: среда разработки не имела доступа к
  `dl.google.com` и к сайтам изданий. Поэтому живые ответы реальных источников проверяются при первом
  запуске, и их статус виден во вкладке «Источники».
- Адреса из каталога частично проверены по сторонним каталогам. Источники уровня `KNOWN`/`DISCOVERY` могут
  оказаться недоступны: приложение покажет ошибку в «Источниках», адрес можно поправить вручную.
- Telegram — только публичные каналы через веб-превью (последние ~20 постов), см. выше.
- Классификация тем и политики построена на ключевых словах. Она прозрачна и настраиваема, но ошибается на
  сложных текстах. Для этого есть ручная пометка «не политика».
- Хранятся только заголовок и фрагмент до 400 символов. Полный текст читается на сайте источника.
- Поиск идёт по сохранённым публикациям (за выбранный срок хранения), а не по всему интернету.
- WorkManager выполняет периодическую задачу не чаще раза в 15 минут, а система может откладывать её в
  режиме экономии энергии.
- HTTP без TLS запрещён (`usesCleartextTraffic=false`): адреса `http://` автоматически меняются на `https://`.

## Данные пользователя и авторские права

- Нет аккаунтов, аналитики, рекламы и секретных ключей. Избранное, история и настройки хранятся только в
  локальной базе Room и не попадают в резервные копии (`allowBackup=false`).
- Сеть используется только для запросов к самим источникам: ленты, страницы Telegram, изображения.
  User-Agent: `NewsHub/1.0 (Android; RSS reader)`.
- Приложение показывает заголовок, короткий фрагмент и ссылку на оригинал. Оригинал открывается в браузере
  (Custom Tabs). Повторные запросы ограничены: условные запросы (ETag/Last-Modified), минимальный интервал
  10 минут на источник, увеличивающаяся пауза после ошибок, соблюдение `Retry-After`.
